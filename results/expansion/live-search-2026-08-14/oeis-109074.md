## Literal counterexample

The merged declaration says, for every natural `n >= 1`,

```text
frac n = (b (n + 1) : Q) / (b n : Q),
```

where the file defines

```text
frac n = C(6n-2, 2n) / (2 C(4n-1, 2n))
b n    = C(3n,n) div (2n+1).
```

At `n=1`, exact evaluation gives

```text
frac 1 = C(4,2) / (2 C(3,2)) = 6/6 = 1,
b 1 = 1,
b 2 = 3,
(b 2)/(b 1) = 3.
```

Therefore the formalized universal statement is false: `1 != 3`.

## Source reconciliation

This is not evidence against the corrected sequence identity.

- The [A005156 b-file](https://oeis.org/A005156/b005156.txt) begins
  `1, 1, 3, 26, 646, ...` at indices `0,1,2,3,4`.
- The shifted ratio printed in the A109074 description and copied into the
  Lean module, `A005156(n+1)/A005156(n)`, is already `3` at `n=1`, while the
  binomial quotient is `1`.  The observed values instead fit the one-step
  lower ratio `A005156(n)/A005156(n-1)` for `n>=1`.
- Independently, the Lean file's local `b` is not A005156: it gives
  `b 3 = C(9,3)/7 = 12`, whereas A005156(3) is `26`.  Agreement through index
  two masks this second defect at the smallest input.

Thus there are two separate transcription problems: a ratio-index shift and
an incorrect definition of the referenced sequence.  The appropriate public
claim is an exact counterexample to the merged formal declaration and its
as-written source ratio, classified as an erratum—not a newly disproved
number-theory conjecture.
