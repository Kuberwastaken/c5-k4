## Literal counterexample

The merged declaration universally quantifies over **real** `x > 1`:

```text
(countRefactorable x : R) >= x / (2 log x).
```

Its counting function takes `floor x` and counts refactorable natural numbers
from one through that value.  At `x=3/2`, the floor is one and the only counted
integer is one, so the left side is exactly `1`.

For the right side, the standard strict inequality `log x < x-1` for positive
`x != 1` gives

```text
0 < log(3/2) < 1/2,
2 log(3/2) < 1,
(3/2) / (2 log(3/2)) > 3/2 > 1.
```

Thus the literal formal bound is false at `x=3/2`.

## Why this is an endpoint erratum

The [A111291 b-file](https://oeis.org/A111291/b111291.txt) concerns the number
of refactorable integers at thresholds `10^n`; this counterexample says
nothing against those terms or against an integer/eventual version of the
lower-bound conjecture.  The Lean module translated an informal counting
variable into every real `x>1`, creating a blow-up interval immediately to the
right of one.

As a calibration, the independent verifier exhaustively computed divisor
counts for every integer `2 <= x <= 1,000,000`.  It found zero integer
violations; the smallest sampled slack was about `0.20136` at `x=7`.  That
bounded result is not evidence for the universal integer conjecture, but it
isolates the discovered failure to the formal real-domain boundary rather
than the intended large-integer phenomenon.

## Method lesson

A lower-endpoint gate should reason about the topology of the quantified
domain, not just substitute its first integer.  Count-step functions divided
by expressions tending to zero are especially high-priority: changing an
informal integer or asymptotic variable into all reals can create an entire
counterexample interval before any sequence search begins.
